# X Img DL NSFW

Chrome用のManifest V3拡張です。ビルドは不要です。

## 導入

1. Chromeで `chrome://extensions/` を開く。
2. 「デベロッパーモード」をオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」で、このREADMEとmanifest.jsonがある `x-image-downloader` フォルダを選ぶ。
4. すでに開いているXのタブを再読み込みする。

更新時は `chrome://extensions/` の拡張機能の再読み込みボタンを押し、Xのタブも再読み込みする。更新後の名称は「X Img DL NSFW」。

## 使い方と保存名

投稿画像の右上の「DL」で、その1枚を保存する。ボタンは最小幅66px・高さ54px（前版の縦横1/2）。
拡大画像にも対応。動画・GIF動画、プロフィール画像、ヘッダー画像は対象外。
Chromeの「ダウンロード前に各ファイルの保存場所を確認する」などの設定・ポリシーは優先される。

## 保存先の設定

Chromeツールバーの拡張機能メニューから「X Img DL NSFW」をクリックすると設定画面が開く。
拡張機能の詳細画面にある「拡張機能のオプション」からも開ける。

- 「保存先フォルダ」に `X画像/お気に入り` と入力して「設定を保存」を押すと、Chromeの既定のダウンロード先の中にそのフォルダを作成して保存する。空欄は既定のダウンロード先へ直接保存。
- Windowsの区切り文字 `\` も使用可能。設定は次のダウンロードから反映される。
- Chromeのdownloads APIは絶対パスを指定できない。別のドライブや任意のディレクトリを使う場合は「毎回保存場所を選ぶ」をオンにして、保存時の画面で選ぶ。またはChromeの「設定」→「ダウンロード」→「保存先」を変更する（Chrome全体に適用）。
- `..` を含むパス、絶対パス、Windowsで使用できない名前は設定できない。同名ファイルの上書き回避と完了通知は従来どおり。

## 保存名

- `@ouran_sakura__` → `ouran_sakura583 (1).jpg`
- `@kimiko9` → `kimiko247 (1).jpg`
- 先頭の `@` と末尾に連続する数字・アンダースコアだけを除く。途中の数字・アンダースコアは保持。
- 数字・アンダースコアだけのIDは `account` にする。
- 100〜999の乱数を投稿ごとに生成し、拡張機能内に保存。同じ投稿の2枚目は同じ乱数で `(2)`。
- 正規化で同じ名前になる別アカウントや乱数の衝突はあり得る。同名ファイルはChromeが追加の連番を付け、上書きしない。
- 拡張子は原寸URLのContent-Typeに合わせる。画像を再圧縮・リサイズしない。

`name=orig` を指定し、HEADで成功と画像形式を確認した後、同じURLをChromeのdownloads APIで保存する。
原寸が取得できない場合は「再試行」と理由を表示し、表示用の低解像度画像には切り替えない。
Xが保持・配信する原寸画像が対象で、撮影時の無加工ファイルを保証するものではない。
HEADを拒否する画像は保存しない。全画像の原寸対応は実ブラウザでの確認が必要。

「取得中」→「保存中」→「保存済み」と進む。完了はChromeがダウンロード完了を通知した時点。
失敗時はボタンにカーソルを置くと理由が表示される。再試行できる。
リポスト・引用では画像リンクの投稿者IDを使う。ページのプロフィール名は使わない。

## 権限と通信

`downloads` と `storage`、X上のcontent script、`pbs.twimg.com` へのホスト権限だけを使用。
原寸確認・画像保存の通信先はXの画像CDN。外部の解析サービス、X APIキー、課金APIは使用しない。
投稿と乱数の対応はstorage.local、処理中のダウンロード情報はstorage.sessionに保存。
XのDOM変更でボタンが表示されなくなる可能性がある。

## ローカルテスト

Node.js 22以降。開発用依存のみをインストールする。拡張機能の動作にはnpmもnode_modulesも不要。

```powershell
npm ci --ignore-scripts
npm test
```

テストは外部通信・Chrome起動・画像ファイルの読み取りを行わない。
ダウンロードAPI・通信をモックし、DOMは合成HTMLを使用する。

## 導入後の実機検証

1. 1枚投稿・複数枚投稿・画像拡大画面でボタンが表示されること。
2. 保存名のID整形、100〜999の乱数、画像番号、実際の拡張子が正しいこと。
3. 同じ投稿の画像で乱数が共通で、拡張機能再読み込み後も保持されること。
4. DL操作でXの画像表示や投稿への移動が発火しないこと。
5. 保存完了前に「保存済み」と表示されないこと。中断時に再試行できること。
6. 原寸URLと保存ファイルの寸法・サイズ・ハッシュを比較すること。VLMは使用しない。
7. スクロール、リポスト、引用で投稿者の誤認やボタン重複がないこと。
